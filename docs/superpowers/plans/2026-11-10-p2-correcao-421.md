# P2: mensagem clara para o 421 no cliente (plano de implementação)

> **For agentic workers:** execute com `meister orchestrate --plan-file docs/superpowers/plans/2026-11-10-p2-correcao-421.json`. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** quando o server HTTP recusa o `Host` (421), o cliente de terminal diz isso e aponta a configuração, em vez de "não consegui falar com o server (ExceptionGroup)".

**Architecture:** uma checagem a mais em `_run` do `client/taxlaw_client.py`, usando os códigos HTTP que o event hook já registra (como o 401). Nos testes, a subida do server vira um auxiliar `running_server(*args)`, e um segundo fixture sobe um server que só aceita `outro.invalid`.

**Tech Stack:** Python 3.13, pytest, SDK `mcp` 2.3.0, `httpx2`.

**Spec:** `docs/superpowers/specs/2026-11-09-transporte-http-design.md` (seções 3 e 5) e `docs/superpowers/specs/2026-11-10-deploy-vps-design.md` (erro de configuração do `--allowed-host`).

## Global Constraints

- Só `client/taxlaw_client.py` e `tests/test_http.py` mudam.
- Nenhuma mensagem contém o token.
- Testes offline (só 127.0.0.1), sem `conftest.py`, sem `sys.path`/`sys.modules`; nenhum server pode ficar rodando depois da suíte.

## Fatos usados aqui (medidos em 2026-11-10)

def running_server(*extra_args):
    """Sobe `python -m taxlaw.http` numa porta livre; gera a URL e encerra no fim."""
    port = free_port()
    env = {**os.environ, TOKEN_ENV: TOKEN}
    process = subprocess.Popen(
        [sys.executable, "-m", "taxlaw.http", "--port", str(port), *extra_args],
        env=env, cwd=ROOT, stdout=subprocess.PIPE, stderr=subprocess.PIPE,
    )
    deadline = time.monotonic() + 30
    while time.monotonic() < deadline:
        with socket.socket() as s:
            if s.connect_ex(("127.0.0.1", port)) == 0:
                break
        time.sleep(0.1)
    else:
        process.kill()
        pytest.fail("o server HTTP não abriu a porta em 30 s")
    yield f"http://127.0.0.1:{port}/mcp"
    process.terminate()
    process.wait(timeout=10)
